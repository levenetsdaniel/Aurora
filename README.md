# Aurora

Учебный проект на C++20 о движении электронов в магнитном поле и моделировании полярного сияния.

Реализованы первые две недели: релятивистский метод Бориса, однородное и дипольное поле, магнитное отражение, диагностика и локализация событий. Текущий пример показывает, как электрон из магнитного экватора движется в область сильного поля и отражается.

## Запуск

В CLion выберите цель **Aurora** и нажмите **Run**. Аргументы не нужны.

Из терминала в папке проекта:

```sh
cmake -S . -B build
cmake --build build --target Aurora
./build/Aurora
```

Нужны CMake 3.20+ и компилятор C++20. Дополнительные библиотеки не требуются. При первом запуске Debug расчёт может занимать несколько секунд: программа разрешает каждое гиродвижение электрона.

## Учебный пример

Пять параметров задаются в начале [main.cpp](main.cpp):

```cpp
const double energy_keV = 100.0;
const double pitch_deg = 45.0;
const double equatorial_distance_RE = 2.0;
const double dt_s = 2e-8;
const double max_time_s = 0.1;
```

Электрон стартует из `(2 R_E, 0, 0)`, где `R_E = 6371000 м`. Начальный импульс лежит в плоскости `xz`, угол с локальным полем равен 45°. Для этого примера задавайте `0 < pitch_deg < 90`, начальное расстояние между `1.02` и `4 R_E`, неотрицательную энергию, положительный шаг и максимальное время. Шаг фиксирован; при изменении параметров его точность нужно проверять отдельно.

По умолчанию расчёт завершается на первом отражении. Чтобы проследить последующее движение между полушариями, установите `config.stop_at_first_mirror = false` и увеличьте `max_time_s`, например до `0.23` с для исходных параметров. Ограничение в 10 миллионов шагов остаётся независимым пределом.

Программа выводит причину остановки, физическое и вычислительное время, число шагов, отклонение энергии и первого адиабатического инварианта. При отражении сравнивает рассчитанное поле с оценкой `B_mirror = B_initial / sin²(pitch_initial)`.

## Результат

Файлы находятся в `results/` относительно рабочей папки; абсолютные пути выводятся в консоль. Повторный запуск их перезаписывает.

- `trajectory.csv` — начальное состояние, каждый сотый шаг и конечное состояние. Колонки: `step,time_s,x_m,y_m,z_m,px_kg_m_s,py_kg_m_s,pz_kg_m_s,kinetic_energy_J,altitude_m,B_T,pitch_deg,p_parallel_kg_m_s,mu_J_T`.
- `events.csv` — обнаруженные отражения и пересечения границ: тип, время, три координаты, модуль поля и ширина временной скобки локализации.

Все величины в СИ, кроме явно обозначенного угла в градусах. Координаты и импульс в CSV приведены к одному моменту времени. Питч-угол при нулевом импульсе не определён и записывается пустой ячейкой. Максимальные отклонения в консоли измеряются на каждом шаге, независимо от разрежения CSV. При ошибке CSV может быть неполным; программа сообщает ошибку и возвращает ненулевой код.

## Как реализована физика

В [DipoleField](include/aurora/fields/DipoleField.hpp) задаются экваториальная нормировка, ось магнитного момента, опорный радиус и нижняя граница области определения. Модель по умолчанию имеет `B_eq(R_E) = 31.2 мкТл` и ось момента `(0,0,−1)`, поэтому на экваторе поле направлено вдоль `+z`.

```text
n = r/|r|, a = направление магнитного момента
B(r) = B_eq(R_E) · (R_E/|r|)³ · [3(a·n)n − a]
+```

Область ближе `0.5 R_E` к центру исключена; сингулярность не заменяется искусственным ограничением поля. Это идеализированный диполь, а не модель реального поля для заданной даты.

[Физические характеристики частицы](include/aurora/physics/ParticleProperties.hpp) вычисляются функцией `particle_properties`: продольная и поперечная компоненты импульса, питч-угол и `mu = p_perp² / (2mB)`. Энергия в заданном магнитном поле сохраняется. `mu` — приближённый адиабатический инвариант: у полной гиротраектории он имеет физические колебания, которые не обязаны исчезать при уменьшении шага.

[TrajectoryRunner](include/aurora/simulation/TrajectoryRunner.hpp) отслеживает смену знака продольного импульса. После регистрации отражения детектор повторно включается только при уверенном движении в обратную сторону: гистерезис исключает повторный счёт колебаний около нуля. Старт с нулевой продольной скоростью сам по себе отражением не считается.

В [EventLocator](include/aurora/simulation/EventLocator.hpp) время события уточняется бисекцией с дробными шагами Бориса из последнего синхронного состояния. Допуск по умолчанию — `10⁻¹¹ с`; он ограничивает ширину скобки, а не полную ошибку физического события. Последняя также зависит от шага всей траектории и накопленной ошибки гирофазы.

Границы примера — сферы `1.02 R_E` и `4 R_E`. При нескольких обнаруженных событиях выбирается самое раннее; конечная строка CSV содержит локализованное состояние. Последний шаг к ограничению времени также может быть дробным. Пересечение внутренней границы здесь означает только выход из расчётной области: переноса энергии и столкновений в атмосфере пока нет.

Возможные причины остановки: `mirror`, `inner_boundary`, `outer_boundary`, `time_limit`, `step_limit`, `numerical_error`. Ошибки исходной конфигурации отклоняются до интегрирования; при численной ошибке возвращаются причина и последнее корректное состояние. Ошибки записи не скрываются как успешное завершение.

Границы проверяются до вычисления поля в конечной точке шага, поэтому перелёт внутрь исключённой области не требует обращения к полю там. Внутри шага поддерживается также вход и выход через внутреннюю сферу по прямому дрейфу. Для произвольно больших шагов, не разрешающих кривизну движения, обнаружение всех пересечений не гарантируется: нужно уменьшать шаг.

## Назначение кода

| Папка | Ответственность |
|---|---|
| `physics/` | Физические формулы: релятивистские преобразования, свойства частицы в поле, гирочастота, период и радиус вращения |
| `fields/` | Вычисление магнитного поля в заданной точке |
| `numerics/` | Один численный шаг интегратора Бориса |
| `simulation/` | Цикл движения, события, остановки и накопление статистики запуска |
| `io/` | Запись рассчитанных данных в CSV |
| `tests/` | Проверки корректности и исследования численной ошибки |
| `tests/reference/` | Аналитические траектории, с которыми сравнивается интегратор |

Рабочие заголовки находятся в `include/aurora/`, реализации — в `src/`. `main.cpp` соединяет эти части в один учебный запуск.

`ParticleProperties` описывает одно состояние электрона. Максимальные отклонения энергии и `mu` за весь запуск накапливает `TrajectoryRunner`. Гирочастота, гиропериод и ларморовский радиус вынесены в [Gyromotion.hpp](include/aurora/physics/Gyromotion.hpp). Аналитическое решение однородного поля находится в [tests/reference](tests/reference/UniformFieldSolution.hpp), в пространстве имён `aurora::test_reference`, и собирается только вместе с тестами.

## Проверки и отчёт второй недели

Проверки включаются отдельно от обычного запуска:

```sh
cmake -S . -B build/tests -DBUILD_TESTING=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build/tests
ctest --test-dir build/tests --output-on-failure
```

Всего 16 проверок: тесты первой недели, нормировка и симметрия диполя, закон обратного куба, наклон оси, отсутствие дивергенции, касательность аналитическим силовым линиям, градиент модуля поля, диагностика, границы и остановки, отражение и повторные отражения, сходимость в неоднородном поле. Время пересечения сферы проверяется по точному решению в однородном поле. Для Debug замените `Release` на `Debug`; для Clang/GCC можно дополнительно включить `-DAURORA_ENABLE_SANITIZERS=ON` в отдельном каталоге сборки.

Генерируемый отчёт второй недели содержит девять сценариев с энергиями 10, 100 и 1000 кэВ и углами 30°, 45° и 60°, сходимость времени и положения отражения и измерение стоимости полного гирорасчёта. Повторить его:

```sh
./build/tests/aurora_week2_report --output results/week2_validation.md
```

Генератор отчёта запускается отдельно, выполняет несколько десятков миллионов шагов и возвращает ненулевой код при нарушении критериев. Численное сохранение энергии само по себе не гарантирует точной фазы и точки отражения. Для сильного различия временных масштабов уменьшение шага требуется даже тогда, когда энергия выглядит постоянной.

Дальше по плану — конус потерь и классификация достижения атмосферной границы. Атмосфера, ансамбли и визуализация сияния пока не реализованы.
