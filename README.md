# Aurora

Учебный научно-вычислительный проект на C++20: от движения электрона до физически обоснованного изображения полярного сияния.

Микропроект первых трёх недель завершён: релятивистский интегратор Бориса, проверки в однородном поле, диполь Земли, магнитное отражение, атмосферная граница, аналитический конус потерь, классификация исходов и воспроизводимые эксперименты.

## Обычный запуск

В CLion выберите **Aurora** и нажмите **Run**. Аргументы не нужны.

Из терминала:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --target Aurora
./build/Aurora
```

Нужны CMake 3.20+ и компилятор C++20. Для графического окна нужен VTK 9.1+ с OpenGL, Charts и IOImage. Если VTK установлен и найден CMake, обычный запуск рассчитывает три примера и открывает визуализацию. На этой машине VTK уже установлен через Homebrew. Если CMake не находит его автоматически, укажите `-DVTK_DIR=/opt/homebrew/lib/cmake/vtk-9.5` при конфигурации. В CLion этот параметр задаётся в CMake options.

Без VTK программа работает в прежнем консольном режиме. Его также можно выбрать при сборке через `-DAURORA_ENABLE_VTK=OFF` или для одного запуска командой `AURORA_NO_GUI=1 ./build/Aurora`. В Debug полный гирорасчёт занимает больше времени; для демонстрации удобнее Release.

Параметры учебного примера находятся в начале `main.cpp`:

```cpp
aurora::ExperimentParameters parameters;
parameters.energy_keV = 100.0;
parameters.pitch_deg = 45.0;
parameters.equatorial_distance_RE = 2.0;
parameters.dt_s = 2e-8;
parameters.max_time_s = 0.1;
parameters.atmosphere_height_m = 100000.0;
```

При 100 кэВ и 45° электрон отражается. При 5° он достигает атмосферы вдоль поля, при 175° — против поля в другом полушарии. Аналитический критический угол для этих положения и высоты — около 16.768°. В консольном режиме программа сначала выводит прогноз, затем фактический исход.

Дополнительные параметры находятся в `ExperimentParameters`: гирофаза, нормировка и ось диполя, внешняя граница, число шагов, частота записи, допуск события и гистерезис. Начальное положение автоматически выбирается на магнитном экваторе, в том числе для наклонённого диполя. Питч-угол принимается от 0° до 180°. Для покоящегося электрона аналитический прогноз направления отсутствует.

Для энергии 10 кэВ времени 0.1 с может не хватить: увеличьте `max_time_s` и при необходимости `max_steps`. Лимит времени не означает ни отражение, ни достижение атмосферы. При изменении энергии и поля проверяйте достаточность шага. Для полного разрешения гиродвижения в CSV уменьшайте `sample_every`; разрежение файла не меняет шаг интегрирования.

## Визуализация микропроекта

В окне слева показаны Земля, атмосферная граница, дипольные силовые линии и вычисленная траектория. Белая точка движется по сохранённой траектории; жёлтый маркер отмечает магнитное отражение, красный — вход в атмосферу. Цвет траектории соответствует `p_parallel / |p|`: при отражении эта величина меняет знак. Толщина линии и размеры маркеров условные; координаты траектории и радиус атмосферной сферы сохраняют физический масштаб.

Справа находятся графики высоты и продольного импульса с общим указателем времени. Вертикальные линии отмечают события; горизонтальные — атмосферную высоту и нулевой продольный импульс. Внизу показаны первые три гиропериода: отдельный плотный участок начальной траектории, записанный с каждым шагом интегратора. Его координаты выражены в метрах относительно старта, ось `B` направлена по начальному полю, `e1` и `e2` перпендикулярны ему. Масштаб по всем трём осям одинаковый. Этот участок статический: он показывает вращение, которое неразличимо в масштабе Земли.

| Клавиша | Действие |
|---|---|
| `1` | Первый пример с углом из `main.cpp`, по умолчанию 45°: отражение и движение после разворота |
| `2` | Питч-угол 5°: вход в атмосферу вдоль поля |
| `3` | Питч-угол 175°: вход в другом полушарии |
| `Space` | Пауза / продолжение |
| `R` | Воспроизвести текущий пример сначала |
| `←` / `→` | Перемотка на 2% физического интервала с остановкой |
| `+` / `−` | Ускорить / замедлить воспроизведение |
| `S` | Сохранить PNG в папке текущего расчёта; путь выводится в консоль |
| `Q` | Закрыть окно |

Мышью можно вращать сцену, колёсиком — менять приближение. Для клавиш используйте английскую раскладку и активное окно VTK. Полная траектория при скорости `x1` проигрывается за 12 секунд. Положение точки интерполируется по физическому времени между записями CSV; новые физические шаги при воспроизведении не рассчитываются.

Три расчёта сохраняются отдельно в `results/visualization/run-.../`. Визуализатор читает `trajectory.csv`, `events.csv`, `summary.csv` и параметры из этих папок. Дополнительный файл `gyro_segment.csv` хранит плотный начальный участок. Для отзывчивости графики и глобальная линия разрежаются примерно до 8000 точек с сохранением начального и конечного состояний и добавлением точных состояний событий. Полные исходные CSV остаются в папке расчёта.

Первый пример продолжает интегрирование после отражения: при 100 кэВ длительность увеличивается как минимум до 0.12 с, а для другой энергии масштабируется обратно скорости. Число разрешённых шагов также увеличивается до этой длительности. Поэтому его итоговый статус обычно `time_limit`, а само отражение зарегистрировано в `events.csv` и отмечено на графике. Для примеров 2 и 3 меняются только угол и остановка на первом отражении; остальные параметры берутся из `main.cpp`. При изменении поля или начального расстояния эти углы могут дать другие физические исходы — окно покажет фактический результат.

## Результаты каждого запуска

Каждый расчёт создаёт отдельную папку `run-<время>-<номер>/`: в `results/` для консольного режима и в `results/visualization/` для окна VTK. Абсолютный путь выводится в консоль. Предыдущие результаты не перезаписываются.

| Файл | Содержание |
|---|---|
| `parameters.txt` | Все входные параметры, без скрытых defaults, с 17 значащими цифрами |
| `summary.csv` | Фактический исход, аналитический прогноз, их сравнение, статус остановки, конечное состояние и максимальные отклонения |
| `trajectory.csv` | Начальное, выбранные промежуточные и конечное синхронные состояния |
| `events.csv` | Отражения и вход в атмосферу: координаты, время, поле, ширина скобки, высота, энергия и импульс |
| `manifest.txt` | Статус выполнения, время, компилятор, режим сборки, платформа, физические константы, версия Git и SHA-256 исходников |
| `source/` | Снимок исходников и CMake-файлов именно скомпилированной версии; `source.sha256` содержит контрольные суммы файлов |

Физические значения записываются в СИ; названия углов с суффиксом `_deg` означают градусы. В CSV события и конечная точка траектории используют одно локализованное состояние. Энергия входа вычисляется из его импульса. Питч-угол при нулевом импульсе не определён, его ячейка пуста.

В `manifest.txt` статус `finished` означает, что расчёт и запись завершены, включая расчёты, остановленные лимитом. Физическая завершённость задаётся отдельно полем `resolved` в `summary.csv`. Статусы `in_progress`, `failed` и `numerical_error` не являются успешным физическим результатом. При ошибке записи часть файлов может оказаться неполной; исключение передаётся пользователю.

Снимок исходников создаётся CMake при сборке и хранится в каталоге сборки под собственным SHA-256. При запуске он копируется к результату. Это сохраняет и незакоммиченные изменения. Запускайте программу из существующего дерева сборки; если версия её снимка удалена, пересоберите программу. Git-информация относится к конфигурации сборки, точное содержимое определяют снимок и контрольные суммы. Случайных чисел пока нет.

## Исходы и аналитическое сравнение

| Исход | Значение |
|---|---|
| `atmosphere_reached` | Первое пересечение атмосферной сферы внутрь |
| `reflected` | Расчёт остановлен на магнитном отражении |
| `escaped` | Пересечена внешняя граница |
| `time_limit` | Недостаточно физического времени; незавершённый случай |
| `step_limit` | Исчерпано число шагов; незавершённый случай |
| `numerical_error` | Ошибка вычислений; сохраняется последнее корректное состояние |

Сравнение принимает значения `match`, `mismatch`, `boundary`, `unresolved`, `not_applicable`. Точные аналитические границы выделяются отдельно; выход за внешнюю границу и отсутствие применимого прогноза не считаются совпадением. Лимиты и ошибки не превращаются в высыпание или отражение.

По умолчанию `stop_at_first_mirror=true`. Если выключить его, электрон продолжит движение между полушариями; остановка по времени после нескольких отражений останется `time_limit`. События отражений будут сохранены. Даже завершённое первое отражение не является доказательством вечного захвата частицы.

## Физика и численная схема

Модель задаёт стационарное поле, `E=0`; частица не влияет на поле. Земля — сфера радиуса `R_E=6371000 м`. По умолчанию ось магнитного момента направлена вдоль `−z`, экваториальное поле на поверхности — 31.2 мкТл:

```text
n = r/|r|, a = единичное направление магнитного момента
B(r) = B_eq (R_E/|r|)^3 [3(a·n)n − a]
gamma = sqrt(1 + |p|²/(m²c²))
v = p/(gamma*m)
K = (gamma−1)mc²
```

Область ближе `0.5 R_E` к центру исключена из определения диполя. Атмосферная граница задаётся как `R_E + atmosphere_height_m`, внешняя — через `outer_distance_RE`. В текущем эксперименте начальная точка должна находиться строго между ними.

Внутреннее состояние Бориса содержит `r^n` и `p^(n−1/2)`. Инициализация выполняет обратный полушаг импульса; обычный шаг обновляет импульс на полном интервале и перемещает координату. Для наблюдения и CSV импульс поворачивается вперёд на полшага и не записывается обратно в интегратор. Время вычисляется как `t0+n*dt`. Устойчивая формула энергии избегает вычитания близких значений `gamma−1` при малом импульсе.

Отражение определяется сменой знака `p_parallel=p·B/|B|`; гистерезис исключает повторный счёт около нуля. Время события локализуется бисекцией с дробными шагами Бориса. Допуск по времени ограничивает скобку корня, но не полную ошибку траектории. Проверка сфер выполняется до обращения к полю в возможной недопустимой конечной точке. Для произвольно больших шагов обнаружение всех пересечений кривой внутри шага не гарантируется; шаг должен разрешать движение.

Для силовой линии с экваториальным радиусом `r_eq` и магнитной широтой `lambda`:

```text
r = r_eq*cos²(lambda)
cos²(lambda_atmosphere) = R_atmosphere/r_eq
sin²(alpha_loss) = B_initial/B_atmosphere
mu = p_perp²/(2mB)
```

Аналитическая оценка поддерживает экваториальный старт в центрированном диполе. Поле атмосферы берётся на той же силовой линии в обоих полушариях. Два конуса находятся около `+B` и `−B`; пограничный угол распознаётся с допуском округления `1e-12` рад. Прогноз предполагает адиабатичность и не управляет интегратором. [Физическая основа конуса потерь](https://farside.ph.utexas.edu/teaching/plasma/Plasmahtml/node23.html).

Энергия должна сохраняться, а `mu` — приближённый инвариант полной орбиты с гироколебаниями. Хорошее сохранение энергии не гарантирует точной гирофазы. Возле границы конуса полная гиротраектория может зависеть от гирофазы и конечного ларморовского радиуса; уменьшение численного шага не обязано устранять отличие от адиабатического прогноза.

## Проверки и завершение третьей недели

Проверки собираются отдельно от обычного запуска:

```sh
cmake -S . -B build/tests -DBUILD_TESTING=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build/tests
ctest --test-dir build/tests --output-on-failure
```

23 проверки охватывают физическое ядро первых двух недель, геометрию конуса, вход и отражение, оба полушария, классификацию незавершённых случаев, ошибки параметров, сохранение конфигурации без потери точности и повторение расчёта. Дополнительно проверяются интерполяция по физическому времени, геометрия силовых линий, загрузка CSV и сохранение исходной частоты записи при плотном наблюдении. Для Debug замените `Release` на `Debug`; в Clang/GCC можно добавить `-DAURORA_ENABLE_SANITIZERS=ON` в отдельной сборке.

При наличии VTK доступна отдельная проверка рендеринга:

```sh
./build/tests/aurora_vtk_smoke results/visualization-preview
```

Она проверяет три физических примера и сохраняет четыре PNG: три конечных кадра и промежуточный кадр первого примера. Повторный запуск читает ранее рассчитанные данные из `runs.txt` в этой папке. Для нового расчёта укажите новую папку. Проверка требует графического контекста и запускается отдельно от CTest.

Полное исследование третьей недели запускается отдельно:

```sh
./build/tests/aurora_week3_report --output results/week3
```

В отдельной папке сессии создаются `cases.csv`, `report.md` и каталоги каждого запуска. Исследуются энергии 10, 100 и 1000 кэВ; оба полушария; углы внутри, на границе и снаружи конуса; шаги 4e-8, 2e-8, 1e-8 с. Для 100 кэВ численная граница уточняется угловой бисекцией до скобки шириной 0.00625°. Отдельно меняется гирофаза на аналитической границе и проверяется учёт лимитов.

Это последовательный полный гирорасчёт десятков траекторий, он занимает заметно больше времени, чем обычный запуск. Генератор возвращает ненулевой код при численной ошибке, неожиданном незавершении, нарушении энергетического допуска 1e-9 или несовпадении прогноза вне пограничной полосы ±0.1°. Все исходы на самой границе сохраняются без требования совпадения с формулой. Скобка — разрешение локального поиска, не статистический доверительный интервал и не доказательство глобальной монотонности.

Сгенерированные Markdown-отчёты, снимки и данные остаются внутри `results/`, который исключён из Git. Для отчётов первых недель доступны прежние тестовые программы `aurora_validation_report` и `aurora_week2_report`.

## Повторение сохранённого запуска

Дополнительная программа доступна только в сборке с тестами:

```sh
./build/tests/aurora_replay results/run-ИМЯ/parameters.txt results/replay
```

Она загружает все параметры, проверяет версию формата и создаёт новый каталог результатов. Неизвестные, повторные или отсутствующие поля отклоняются. При одинаковой сборке и параметрах расчёт детерминирован. Новая версия программы может дать иной результат, поэтому для точного воспроизведения старого запуска используйте его снимок исходников и записанные режим и компилятор:

```sh
cmake -S results/run-ИМЯ/source -B build/from-snapshot -DBUILD_TESTING=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build/from-snapshot
./build/from-snapshot/aurora_replay results/run-ИМЯ/parameters.txt results/replay
```

Проверка отдельных файлов снимка на macOS/Linux выполняется из его каталога командой `shasum -a 256 -c source.sha256`. SHA-256 самого файла `source.sha256` должен совпадать с полем `source_sha256` манифеста. Различия округления между компиляторами и архитектурами возможны.

## Назначение кода

- `physics/` — релятивистские формулы, свойства частицы, гиродвижение и аналитический конус потерь.
- `fields/` — модели магнитного поля.
- `numerics/` — один шаг Бориса.
- `simulation/` — цикл движения, события, параметры эксперимента и классификация исходов.
- `io/` — CSV, сохранение и чтение параметров, манифест и файлы запуска.
- `visualization/` — чтение результатов для показа, интерполяция по времени, геометрия силовых линий и окно VTK.
- `tests/reference/` — аналитические траектории для проверки интегратора.
- `tests/` — автоматические проверки и дополнительные программы исследования.

Микропроект заканчивается регистрацией входа в атмосферу. Столкновения, энерговыделение и свечение пока отсутствуют. Следующий этап — ансамбли частиц и физическая нормировка источника.
